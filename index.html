Arch 1. 화면 밖의 비상구: 숨겨진 백도어(Backdoor) 패턴
💡 Story: 설정 메뉴조차 열리지 않는다면?
배포 후 심각한 렌더링 에러로 하얀 화면만 뜨는 이른바 'White Screen of Death' 상황을 가정해 봅시다. 사용자는 앱 내의 '초기화' 버튼에 접근조차 할 수 없습니다.
  • 전역 인터럽트 (Global Interrupt): 이럴 때 DOM 렌더링 상태와 완전히 독립적으로 동작하는 전역 이벤트 리스너(예: Insert 키 입력 또는 좌표 (0,0) 연속 터치)가 유일한 탈출구가 됩니다.
  • 관심사 분리: 일반 사용자에게 노출되면 대참사(CS 폭주)가 일어날 파괴적 버튼을 숨겨두면서도, QA와 개발자에게는 즉각적인 디버깅 환경을 제공하는 실무의 단골 패턴입니다.
Cache 2. PWA의 양날의 검: 캐시 좀비(Cache Zombie) 현상
💡 Story: 왜 코드를 고쳤는데 안 바뀔까?
PWA(Progressive Web App)는 오프라인에서도 작동하도록 서비스 워커를 통해 정적 파일들을 강력하게 캐싱합니다. 하지만 이것이 업데이트 시 발목을 잡습니다.
Cache Sticking브라우저가 이전 버전의 JS 전역 컨텍스트를 계속 서비스하여 새로고침(F5)만으로는 코드가 갱신되지 않습니다.
Schema Mismatch데이터베이스 구조를 바꿨는데, '과거의 JS 코드'가 '새로운 데이터'를 파싱하려다 충돌해 앱이 죽어버립니다.
🎯 해결책: 단순 변수 초기화가 아닌, caches.keys()를 순회하며 caches.delete()로 저장소를 비우고, 서비스 워커를 강제로 unregister하여 연결을 물리적으로 끊어버리는 '소프트웨어적 소각(Purge)'이 필요합니다.
Guard 3. 사용자를 멈춰 세우는 마법: 인지적 마찰(Cognitive Friction)
💡 Story: "정말 삭제하시겠습니까?"는 왜 실패할까?
  • 단순한 확인(Confirm) 팝업은 사용자의 '근육 기억(Autopilot)'을 이기지 못합니다. 사람들은 경고문구조차 읽지 않고 기계적으로 [확인]을 누르는 경향이 있습니다.
  • 의도된 불편함: 이를 방지하기 위해 사용자가 직접 delete라는 단어를 타이핑하도록 강제(Cognitive Friction)합니다. 인지적 비용을 지불하는 순간, 뇌는 비로소 '오토파일럿'을 끄고 자신의 행동이 가져올 심각성을 자각하게 됩니다. (GitHub에서 리포지토리를 삭제할 때 이름을 직접 치게 만드는 것과 동일한 원리입니다)
